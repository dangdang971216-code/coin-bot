- main: canonical status/snapshot 읽기와 Telegram 표시만 담당하며 독립 성과 계산 금지.
- guard: ZIP·manifest·배포·systemd·MainPID·source hash·runtime 검수.
- 같은 값과 같은 원장의 active writer는 반드시 owner 1개다.

5. 진짜 단일화 기준
- 새 함수를 뒤에 덧붙여 마지막 정의만 실행시키는 것은 단일화가 아니다.
- caller→writer→reader→cache→handler를 추적한 뒤 구 정의·wrapper·fallback·alias chain·죽은 run_cycle/handler를 실제 삭제한다.
- 완료 조건: 동일 기능 정의 1개, 직접 writer 1개, active owner 1개, wrapper 0, fallback 0, 죽은 본선 0, tail-after-main=False.
- active path 함수·handler·reader·writer·COMMANDS에는 버전 번호를 최대한 남기지 않는다.
- 기능을 함부로 빼지 않는다. 삭제 대상은 중복 구현·구 fallback·반복 저장·죽은 코드·구 실험 공개경로다.

6. S1·S2·S3
- S1/S2/S3 분류는 모두 유지한다.
- S3는 observation-only이며 삭제 대상이 아니다. 실제 매매 경로만 차단한다.
- 신규 S3 필수값: observation_only=True, open_eligible=False, paper_bot_open=False, trade_ready=False.
- S3는 final S1, hold, paper selector, safety, OPEN writer에 들어가면 안 된다.
- 좋아진 S3는 기존 row를 승격하지 않고 새 candidate/direct key로 S2→S1을 다시 거친다.
- 과거 S3 OPEN/CLOSED는 삭제하지 않고 ‘과거 관찰경로 유입’으로 별도 표시한다.

7. OPEN·CLOSED·성과 단일본선
- 원본 OPEN/CLOSED/trade_log/decision/exact 원장은 삭제·축소·현재값 재계산 금지.
- OPEN에는 당시 구조선·TF·source·RR·공간·추격·spread·slippage·비용·timing·시장상태·build를 append-once로 봉인한다.
- CLOSED 저장 순서: append→fsync→tail 확인→decision CLOSED→성공 확인→OPEN 제거→알림.
- append 또는 decision 실패 시 OPEN 유지. OPEN 선삭제 금지.
- 성과 원본은 paper_bot_closed.jsonl + direct decision state다.
- paper systemd owner 1개가 canonical snapshot 1개를 쓴다.
- /version_score·/performance_lab·/trade_review는 같은 snapshot 읽기 전용이다.
- exact는 OPEN 당시 ALT_SWING_V977, cutover 이후, direct key 존재, decision=CLOSED, 같은 key 첫 committed CLOSED 1건이다.
- ticker·pos_id·시간근접·알림 trace 추정 연결 금지.
- 과거 OPEN에 없던 시장값은 현재값으로 복원하지 말고 UNKNOWN으로 남긴다.

8. worker 구조 감사와 정리 순서
- 0-A: service·ExecStart·MainPID·cmdline·actual source·VERSION/BUILD·hash·UID/GID·active owner 감사.
- 0-B: 각 worker 내부 중복 정의·writer/reader·wrapper/fallback·죽은 본선 감사.
